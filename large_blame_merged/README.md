# Large-file blame timeout scenario (merged PR)

Reproduces the work-metrics classification bug where one oversized file makes a whole
commit fail and get re-queued every hour forever.

## Background

For GitHub and GitLab, work-metrics runs remote `git blame` twice (commit and parent) for
every modified file with deleted lines. On large files GitHub's GraphQL blame times out after
about 10 s (`504 Gateway Timeout` / GraphQL error). Blame worked up to ~705 KB and failed
from ~1.98 MB upwards. Today a single failed file drops the entire commit as "partially
classified, will retry next run", and because the file never shrinks, the commit is stuck.

Azure DevOps and Bitbucket clone locally for blame and are not affected.

## Files

| File | Size | Expected GitHub blame |
|---|---|---|
| `blame_ok_700kb.json` | ~700 KB | succeeds |
| `blame_fail_2mb.json` | ~2 MB | times out |
| `blame_fail_5mb.json` | ~5 MB | times out |
| `small_a.txt`, `small_b.txt`, `small_c.txt` | < 1 KB | succeeds |

Files are generated by `gen_fixtures.py` (one JSON record per line).

## Commits (in order)

1. **seed** – adds all files. Additions only, so no blame is needed.
2. **mixed** – deletes/rewrites lines in both oversized files *and* the three small files.
3. **large-only** – deletes/rewrites lines only in `blame_fail_5mb.json`.
4. **control** – deletes/rewrites lines in `blame_ok_700kb.json` and `small_a.txt` only.

## Expected behaviour after the fix

| Commit | Before fix | After fix |
|---|---|---|
| seed | classified | classified |
| mixed | dropped, retried every hour, never completes | small files classified; the two oversized files skipped and recorded as blame-skipped; commit marked complete |
| large-only | dropped, retried every hour, never completes | commit marked complete with the oversized file skipped; not re-queued |
| control | classified | classified (unchanged) |

Also check that:
- no commit from this branch stays at the head of the queue across runs;
- the number of GitHub API calls for this branch does not grow on each hourly run;
- new work / rework for the small files shows up on the dashboard.
